Refusal mechanisms: a prototype

Throwaway prototype. The question: if each adapter's classification were stored as a short list of refusal mechanisms (for example, "refuses any comparison whose operand is a computation"), each keyed on features read mechanically from the planner's wire fixtures, would joining the two reproduce today's hand-written actions.json? And would a new corpus action come out classified correctly? The mechanisms here were induced automatically from today's data, so they approximate what an adapter author would write.

Headline

New action? 5-fold cross-validation: mechanisms are induced from 4/5 of the actions and the held-out fifth is treated as brand new. False refusal: derived as refused, but the adapter translates it. Missed: derived as translated, but the adapter refuses it. Both mistakes are loud: the harness fails the run, just as it does today on a wrong hand classification.
